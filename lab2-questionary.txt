To optimize memory usage when mapping the KERNBASE region, we switched from using standard 4KB pages to using large 4MB pages through the Page Size Extension (PSE) feature. First, we added a check (cpu_supports_pse()) to detect if the processor supports PSE. If supported, we enabled it by setting the PSE bit in the CR4 register (enable_pse()). Instead of creating many page tables, we mapped KERNBASE directly in the page directory using 4MB pages, setting the PTE_PS bit to indicate a large page. This approach saves memory and improves performance by reducing page table overhead.

We also made sure this optimization only happens if the CPU supports it; otherwise, we fall back to the regular 4KB mapping. Finally, we updated check_va2pa() to properly handle 4MB pages by checking for the PTE_PS bit, ensuring virtual-to-physical address translation works correctly for both 4KB and 4MB mappings.
